# 自动化通知渠道扩展规划规范

## 1. 背景与目标
目前系统依赖用户主动登录网页查看缴费排期，或手动将 ICS 文件导入系统日历。对于周期长、频次低（通常一年扣一次）的家庭保单，极易发生：
- **银行卡扣费失败但用户不知情，超过 60 天宽限期保单失效**；
- **车险提前 30 天续保优惠窗口期错过，甚至脱保上路面临交警处罚**；
- **消费型医疗险未在到期前续费，导致保证续保权益中断**。

本规划旨在为系统构建**全自动化多通道消息提醒引擎（Automated Notification Hub）**。

---

## 2. 核心通知场景与触发规则

| 通知类型 | 触发时机 | 提醒内容与建议动作 |
| :--- | :--- | :--- |
| **车险续保黄金期** | 商业险/交强险到期前 30 天 | 提示车险即将到期，建议联系各大保险公司报价对比方案。 |
| **保费扣款预告** | 保费扣款日（paymentMonthDay）前 7 天 | 提醒预留充足资金至扣费银行卡，防止扣款失败。 |
| **扣款当日核实** | 保费扣款日当天早晨 09:00 | 提醒查看银行扣款短信或网银流水，进入系统确认核验。 |
| **宽限期倒计时预警** | 扣款日之后第 30 天、第 50 天（保单仍处于待确认状态） | **高危红色预警**：保单扣费可能未成功，距 60 天宽限期失效仅剩 X 天，请立即补扣！ |
| **车辆年检到期** | 行驶证年检到期前 15 天 | 提示申领电子检验合格标志或预约上线检测。 |

## 3. 多通道接入架构设计

系统设计为轻量插件化通知通道体系，用户可在前端系统设置中配置并开启：

### 3.1 Webhook 群机器人（企业微信 / 钉钉 / 飞书）
* **原理**：基于标准 HTTP POST JSON 调用群机器人 Webhook 地址。
* **企业微信 Markdown 消息体示例**：
```json
{
  "msgtype": "markdown",
  "markdown": {
    "content": "### 🔔 家庭保险扣费提醒\n> **产品名称**：<font color=\"info\">国寿福终身寿险（至尊版）</font>\n> **被保人**：陈峰\n> **应缴保费**：<font color=\"warning\">¥6,942.43</font>\n> **扣费日期**：2026-03-29 (还有 7 天)\n> **扣费卡号**：招商银行 (尾号6828)\n\n请确保扣款账户余额充足以免影响保单权益。"
  }
}
```

### 3.2 苹果 iOS Bark 极简推送
* **原理**：面向 iPhone 用户，只需配置个人 Bark Key，直接推送系统级横幅通知与声音提醒。
* **特点**：零配置、无需搭建 App、无需任何云端中转服务器、延迟低。

### 3.3 SMTP 邮件推送 (Email Notification)
* **适用场景**：发送月度/年度保单体检摘要、缴费提醒。
* **配置项**：SMTP 服务器地址、端口（465/587）、发件人邮箱与授权码。

---

## 4. 后台扫描与调度机制

1. **守护进程 / 定时任务调度器 (Scheduler)**：
   - 采用标准 Python `threading.Timer` 或 `apscheduler` 轻量集成；
   - 每日固定时刻（如早晨 08:30）执行一次扫描任务。
2. **状态防重复触发控制 (Deduplication Lock)**：
   - 每条触发提醒在 `payment_records.json` 或 `notification_logs.json` 记录 `lastNotifiedDate` 和 `notifiedChannels`，同一事件周期内严格只提醒一次，防止重复骚扰。
3. **前端测试通道连通性**：
   - 设置界面提供「发送测试消息」按钮，一键验证 Webhook 或 Bark 是否配置成功。

---

## 5. 后续演进路线
- **Phase 1**：后端实现通知配置文件 `config/notifications.json` 与 Webhook / Bark 发送器。
- **Phase 2**：每日定时扫描函数打通，接入扣费前 7 天与到期前 30 天规则。
- **Phase 3**：前端设置面板（通道配置、开关、一键测试）。
